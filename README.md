# 📚 책갈피 (Bookmark)

> 책을 읽고, 기록하고, 다음 읽을 책을 추천받는 **기록 기반 도서 추천 서비스**  
> 독서를 기록으로 남기고, 기록을 다음 독서로 연결합니다.

---

## 🔍 프로젝트 소개

**책갈피**는 독서 경험을  
**독서 → 기록 → 추천 → 다시 독서**로 이어주는 웹 서비스입니다.

독서를 마친 뒤 남긴 리뷰와 독서 중 작성한 갈피 기록을 기반으로  
사용자의 사고 흐름과 독서 맥락을 분석해  
다음 읽을 도서를 추천하는 것을 목표로 합니다.

---

## 🎯 기획 배경

- 독서 기록이 메모 앱, SNS 등으로 파편화되어 관리되기 어려움
- 기존 독서 서비스는 완독 후 리뷰 중심으로 독서 과정이 남지 않음
- 장르·별점 기반 추천은 개인의 독서 관점을 충분히 반영하지 못함

👉 **기록을 중심으로 독서 경험을 축적하고, 다음 독서로 연결하는 서비스 필요**

## ✨ 주요 기능

### 1️⃣ 독서 상태 관리 – 서재 기능
- 읽는 중 / 완독 / 중단 상태 관리
- 독서 시작일·완독일·평점 기록
- 사용자별 독서 이력 관리

#### 설계 포인트
- 초기 데이터 부족 문제 해결을 위해  
  **검색은 Google Books API**,  
  **실제 조회된 도서만 DB에 저장**

---

### 2️⃣ 독서 기록 – 갈피 & 리뷰
- 독서 중 인상 깊은 문장과 생각을 **갈피**로 기록
- 완독 후 책 전체에 대한 **리뷰 작성**
- 독서의 과정과 결과를 분리하여 저장

---

### 3️⃣ 리뷰 기반 도서 추천
- 사용자가 작성한 리뷰 텍스트를 임베딩 벡터로 변환
- 도서 벡터 DB와의 의미적 유사도 비교
- 유사도가 높은 5권의 도서를 추천
- 리뷰에서 추출한 키워드와 추천 이유 함께 제공

---

### 4️⃣ 커뮤니티 기능
- 갈피·리뷰에 댓글과 좋아요
- 관심 있는 사용자를 팔로우
- 기록을 중심으로 한 피드 제공

---

```

제한된 시간 안에서 완성도를 확보해야 하는 상황에서, AI의 도움을 받아 빠르게 기능을 구현하고 이후 점진적으로 보완해 나갔다면 더 높은 퀄리티의 결과물을 만들 수 있었겠다는 생각이 들었습니다.

앞으로는 AI를 무조건 배제하거나 의존하는 것이 아니라, 현실적인 상황에 맞게 활용하는 방법에 대해 고민해보는 계기가 되었습니다.
AI를 개발을 대신하는 도구가 아니라, 생산성과 판단을 보조하는 도구로 잘 활용하고자 합니다.

또한 단순히 과제를 완성하는 프로젝트가 아니라 실제 운영되는 서비스를 가정하고 개발했기 때문에, 데이터 저작권 문제나 외부 API 사용 시 발생할 수 있는 현실적인 제약들을 깊이 고민할 수 있었습니다.
이 과정에서 다양한 API를 비교·활용하며 데이터 품질이 서비스 완성도에 얼마나 큰 영향을 미치는지도 체감했습니다.

```
